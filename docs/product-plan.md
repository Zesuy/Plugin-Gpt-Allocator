# CPA Route Allocator 产品与工程计划

本文档记录当前已经确认的产品方向和后续整体实现范围。后续实现应以本文档为基线；如果需求发生变化，先更新本文档，再修改代码。

## 1. 产品定位

这是一个只供个人使用的 CLIProxyAPI 原生插件，目标不是做通用监控平台，而是把以下关系管理清楚：

```text
凭据 → Listener → Selector → 请求发生时的节点 → 实际公网 IP
```

页面应参考 Cli-Proxy-API-Management-Center（CPAMC）的真实“凭据库工作台”实现方式，而不是只借用颜色和圆角。

CPAMC 的重要参考结构：

- `AuthFilesPage`：页面头部、Provider Tabs、工具栏、卡片网格、分页和批量操作。
- `AuthFileCard`：选择框、Provider 图标、类型标签、状态标签、主身份、文件名、警告区、健康区、元数据行、操作栏和开关。
- `AuthFilesToolbar`：搜索、状态分段、排序、显示选项。
- `ProviderStatusBar`：按时间桶展示近期成功/失败，而不是一个没有上下文的总数。
- `AuthFileDetailsSheet`：复杂配置和完整详情放到抽屉，而不是塞进卡片。

本项目使用内嵌 HTML/CSS/JS，不直接复制 React 组件，但应保持相同的信息层级和交互分工。

## 2. 已确认且必须保留的功能

- 支持 CPA 和 sub2api 格式凭据导入，并自动转换到 CPA Auth 格式。
- 完整邮箱作为默认名称；同邮箱不同工作区、Access Key 或鉴权上下文时追加 `_1`、`_2`。
- 可在面板中用别名覆盖显示名称。
- 同一账号、同一工作区再次导入时更新凭据内容，保留原分组和路由。
- Upload 只负责上传；已有凭据换组时拒绝。
- API 导入允许更新凭据内容，但不改变已有分组和路由。
- 分组增删改查、拖动排序；分组顺序影响导入和接管下拉框。
- Listener / Selector 增删改查、复制、编辑弹窗。
- 可发现并接管 CPA 已有本地凭据；接管后可继续管理。
- 停止管理时保留 CPA Auth 文件，并向用户明确提示被移除的凭据。
- 按 CPA Management API 控制凭据启用/禁用。
- Codex 额度手动查询，额度按独立窗口展示，不合并成单一数字。
- 所有操作使用短 Toast 或对话框，不把原始 JSON 当作提示内容。
- 不新增 HTTP 端口，继续使用 CPA 已有 Management API 和插件资源路径。

## 3. 页面信息架构

主入口建议分为：

1. **凭据**：默认页面，负责凭据卡片和日常管理。
2. **Listener 出口**：负责 Listener、Selector、节点、公网 IP 和诊断。
3. **分组**：负责分组策略、排序和路由策略。
4. **导入 / 接管**：负责上传、粘贴、预览、API 导入和本地凭据接管。

当前总览中的“插件主机公网 IP”和全局延迟指标不再作为主要 UI 内容。旧接口可以暂时保留兼容，但新 UI 不应展示它们，避免把插件主机出口误认为 Listener 出口。

## 4. 凭据卡片工作台

### 4.1 页面头部

参考 CPAMC `VaultHeader`：

```text
凭据管理
8 个凭据 · 6 个启用 · 1 个异常

[刷新] [上传 / 粘贴] [发现本地凭据]
```

不再使用当前四个大型全局指标卡抢占首屏空间。

### 4.2 分组 / 类型 Tabs

CPAMC 使用 Provider Tabs；本项目主要使用分组 Tabs：

```text
全部 8    boom 2    primary 3    backup 3
```

可以同时提供状态筛选：

```text
全部    启用    停用    问题
```

“全部”视图仍按分组显示；选择某个分组后只显示该分组卡片。分组顺序来自拖动排序。

### 4.3 工具栏

参考 CPAMC `AuthFilesToolbar`：

- 搜索邮箱、别名、工作区、Listener、节点。
- 启用 / 停用 / 问题分段筛选。
- 默认排序、邮箱排序、优先级排序。
- 显示选项：卡片数量、紧凑模式、是否显示额度摘要。
- 后续可接入批量选择和批量操作栏。

### 4.4 单张凭据卡片

卡片采用 CPAMC 的固定区域，不做成表格行：

```text
┌─────────────────────────────────────┐
│ □ [Codex] offer.martin763@mail.com  │ [已启用] │
│ offer.martin763@mail.com.json       │
│                                     │
│ 分组 boom                            │
│ Listener CPA-03                     │
│ 当前节点 JP-日本高速05               │
│ 额度 周 73% 可用                     │
│                                     │
│ [详情] [额度] [编辑]           启用 ◉ │
└─────────────────────────────────────┘
```

卡片内容规则：

- 顶部显示选择框、Codex 图标、类型标签、启用状态。
- 主身份显示别名或完整邮箱；文件名为次级文本。
- 工作区、分组、Listener 和当前节点是元数据，不占用大表格列。
- 额度错误、工作区失效等显示为卡片内 warning 区。
- 额度默认显示一行摘要；完整 primary/secondary 窗口放到详情抽屉。
- 凭据卡片不展示请求质量；网络质量属于 Listener 和节点维度，避免重复信息并降低卡片密度。
- 长邮箱、节点名、Auth 文件名允许省略，但必须支持 title 或详情查看。
- 卡片底部只放高频操作，其余放入更多菜单。
- 禁用卡片降低内容对比度，但不能隐藏编辑和重新启用入口。

建议桌面端使用约 `minmax(280px, 1fr)` 的响应式网格，移动端单列；默认紧凑模式和每页 24 个，避免凭据数量增加后页面过长。

## 5. Listener 卡片工作台

Listener 不再使用普通配置表格，而是使用与凭据相同的卡片语言：

```text
┌──────────────────────────────────────────┐
│ [Listener] CPA-03          [正常] [IP重复] │
│ socks5://192.168.5.1:7913                │
│ Selector: CPA-03                         │
│                                          │
│ 当前节点                                  │
│ JP-日本高速05                             │
│                                          │
│ 实际公网出口                              │
│ 203.0.113.20 · US / SJC                  │
│                                          │
│ Listener 请求                             │
│ 总耗时 680 ms · 首字节 430 ms             │
│                                          │
│ 节点请求质量                              │
│ 成功 31 · 网络断开 0 · 上游错误 2          │
│                                          │
│ [查看节点] [刷新诊断] [选择节点] [去除重复] │
└──────────────────────────────────────────┘
```

Listener 卡片显示的是当前 Listener 的实际出口，不显示插件主机公网 IP。

Listener 主卡同样采用紧凑布局，桌面端网格最小宽度约 280px；节点质量只保留一行摘要，完整候选节点在展开区查看。

点击“查看节点”后，在卡片下方展开紧凑节点卡片，而不是跳转到一张大表格。

## 6. 节点卡片和节点级统计

统计维度必须是：

```text
route_slot_id + node_name + transport
```

同名节点被不同 Listener 使用时不直接合并，因为实际代理链可能不同。

节点卡片至少显示：

- 当前 / 可选 / 不可用状态。
- Mihomo 最近延迟和历史平均延迟。
- 真实请求 p50 / p95 响应时间。
- SSE 和 WebSocket 分开统计。
- 网络断开数量、超时数量和比例。
- OpenAI 4xx/5xx 数量，但不将其算作节点网络故障。
- 当前公网 IP或“未验证”。
- 最近检测时间和数据是否过期。

示例：

```text
JP-日本高速05
当前节点 · 正常
Mihomo 420 ms
真实请求 p95 2.4 s
网络断开 0 / 31
OpenAI 错误 2
公网 IP 203.0.113.20
```

节点详情抽屉可以显示最近 15 分钟、1 小时或 6 小时的趋势和错误明细。错误只展示脱敏后的短原因，不展示原始 JSON。

## 7. 响应时间、拥堵和网络断开

### 7.1 错误分类

| 类型 | 示例 | 节点归因 |
|---|---|---|
| 成功 | 正常完成 | 成功请求 |
| 上游错误 | OpenAI 401/403/429/500 | 不降低节点健康度 |
| 网络错误 | EOF、连接重置、TLS 失败、代理断开 | 归因到实际节点 |
| 超时 | dial timeout、TLS timeout、context deadline | 归因到实际节点 |
| CPA 内部错误 | 插件或 CPA 自身处理失败 | 独立统计 |
| 未知错误 | 信息不足 | 不参与自动判断 |

如果 CPA 把网络错误包装成 HTTP 502，只有在错误正文明确包含 transport / connection / timeout 证据时才归入网络错误；否则进入未知分类，避免误判。

### 7.2 拥堵状态

CPA / Mihomo 没有直接的节点拥堵值，因此使用“拥堵倾向”，而不是伪装成绝对结论。

依据包括：

- 节点近期 p95 响应时间相对于自身历史基线明显升高。
- 首字节时间持续升高。
- 网络断开和超时集中发生。
- Mihomo 节点探测延迟同步升高。

状态包括：

- 正常
- 延迟升高
- 拥堵倾向
- 网络不稳定
- 节点不可用
- 上游错误较多
- 数据不足

“上游错误较多”不会触发节点切换；“网络不稳定”和“拥堵倾向”才会影响去重候选排序。

### 7.3 请求归因

CPA usage 记录中的 `AuthIndex` 用于找到凭据，再找到 Listener。插件保存 Selector 切换时间线，根据 `RequestedAt` 判断请求开始时实际使用的节点。

如果没有 AuthIndex、走默认路由、Listener 不受 Allocator 管理，或节点由外部修改且无法还原，则归入“未归因请求”，不能随意算到当前节点。

## 8. Listener 公网 IP检测

公网 IP探测链路为：

```text
插件 → Listener → Mihomo Selector → 当前节点 → chatgpt.com/cdn-cgi/trace
```

只检测当前节点时，不主动切换线路。候选节点只有在用户手动验证或执行去重时才探测。

诊断结果包括：

- IP
- 地区和机房
- 总耗时
- 首字节耗时
- 检测时间
- 失败原因

缓存键使用 `route_slot_id + node_name`，不能只使用节点名称。

## 9. “去除重复”功能

这是人工确认功能，不是自动轮换。

### 9.1 分析面板

用户点击 Listener 卡片上的“去除重复”后，先打开分析抽屉：

```text
发现 3 个 Listener 使用相同公网 IP

203.0.113.20
├─ CPA-03 · JP高速05 · 2 个凭据
├─ CPA-04 · JP高速05 · 3 个凭据
└─ CPA-06 · JP专线01 · 1 个凭据
```

同时显示共享 Selector 和影响范围。

### 9.2 候选排序

候选节点按以下顺序排序：

1. 当前没有被其他 Listener 使用，公网 IP待验证。
2. Mihomo 存活。
3. 网络稳定。
4. 没有拥堵倾向。
5. 真实请求 p95 较低。
6. 最近断开次数少。
7. 已被其他 Listener 使用，需要再次验证公网 IP。
8. Mihomo 不可用。

未知 IP 的候选必须标记“待验证”，不能伪装成可安全切换。

### 9.3 执行流程

1. 每个重复组固定保留第一条 Listener，不切换整组所有成员。
2. 保存其余相关 Listener 的原始节点。
3. 逐个切换 Selector，优先尝试当前未占用的未知公网 IP 节点。
4. 等待 Mihomo 确认切换完成。
5. 通过对应 Listener 检测公网 IP和响应时间。
6. 将新 IP 与全部 Listener 比较；只有全局不重复且网络质量可接受时才保留切换。
7. 如果失败、仍重复或节点不稳定，恢复原节点。
8. 继续尝试下一个候选。
9. 生成成功、失败、阻止和回滚报告。

共享 Selector 必须明确提示：

```text
CPA-03、CPA-04 共用 Selector：proxy-group-1
切换该 Selector 将同时影响 2 个 Listener 和 5 个凭据。
```

第一版不做隐式拆分。无法单独影响某个 Listener 时，应明确拒绝单独切换，而不是悄悄影响其他凭据。

## 11. 数据保存策略

持久配置继续保存：

- 凭据、别名、分组和路由归属。
- Listener / Selector绑定。
- 当前节点。
- Selector切换时间线的必要摘要。

运行统计使用有上限的内存环形缓存：

- 按 Listener、节点、传输方式聚合。
- 节点统计每个 `route_slot_id + node + transport` 桶最多保留最近 1000 条，且最长保留 6 小时；超过任一上限即淘汰。
- 全局 SSE / WebSocket / 非流式统计目前只在进程内累计，不写入状态文件；插件重启后从零开始。
- Selector 切换历史只在进程内保留每个 Listener 最近 100 次，插件重启后清空。
- 不保存凭据正文和完整响应正文。
- 插件重启后所有运行统计清空，UI 应明确显示“本次启动以来”或“暂无数据”，不能让用户误以为是长期历史。

出口探测与真实请求统计是两组不同数据，必须分开展示：

- **出口探测**：插件经由某个 Listener / 当前节点请求 `chatgpt.com/cdn-cgi/trace` 得到的单次公网 IP、首字节和总耗时。
- **真实请求统计**：CPA `usage.handle` 记录的请求样本，按 Listener、节点和 SSE / WebSocket / 其他传输方式聚合，计算请求数、TTFT 均值、总耗时均值和 p50 / p95。
- 两组数据的采样时间、请求类型和样本数量都可能不同，因此不要求数值相等；标签必须包含“出口探测”或“真实请求”。

`share_least` 的容量统计只计算启用凭据。停用凭据仍保留原来的路由归属，但不占用 Listener 的共用次数；重新启用时，如果发现该 Listener 已被其他启用凭据共用，界面必须先提示用户选择“保持共用”或“重新分配到其他 Listener”。

所有诊断结果必须带：

- `checked_at`
- `expires_at`
- `source`
- `error`

## 12. 实施顺序

### 第一阶段：UI工作台重构

- 凭据表格改为 CPAMC 风格卡片网格。
- 增加页面摘要、分组 Tabs、搜索、状态筛选、排序和显示选项。
- Listener 改成卡片结构。
- 增加详情抽屉和统一操作栏。

### 第二阶段：诊断数据

- 扩展 usage 记录解析，加入 AuthIndex、失败正文和传输信息。
- 建立错误分类器。
- 建立 Listener + 节点 + 传输方式的滚动统计。
- 增加 Selector 切换时间线。
- 增加 Listener 当前节点公网 IP和响应时间探测。
- Listener 卡片和节点卡片显示响应、拥堵和网络断开信息。

### 第三阶段：去除重复

- 重复 IP聚合。
- 共享 Selector 影响分析。
- 候选节点质量排序。
- 预览、确认、逐个切换、验证、回滚和结果报告。

### 第四阶段：验证与交付

- 测试 OpenAI 4xx/5xx 不被误判为节点故障。
- 测试 EOF、超时、连接重置等网络错误能归因到正确节点。
- 测试 Selector 切换前后请求归因正确。
- 测试共享 Selector 不会被隐式拆分或误操作。
- 测试 Listener 公网 IP和节点延迟显示。
- 测试去重失败时能恢复原节点。
- 完成 amd64 构建并按进度提交 Git。

## 13. 默认行为和边界

- 去重只处理已配置且启用的 Listener。
- 不自动定时切换节点。
- 不因为 OpenAI 401、403、429、500 自动禁用凭据或切换节点。
- 无法确认错误来源时归入未知，不强行归因。
- 共享 Selector 的切换影响必须在确认前展示。
- 没有足够样本时不显示虚假的平均值或拥堵结论。
- 不再把插件主机公网 IP当作 Listener 公网 IP展示。
